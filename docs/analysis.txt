Login Flow:
  1. User clicks "Login" button
  2. Button calls signIn("azure-ad") from next-auth/react
  3. POST to /api/auth/signin/azure-ad with CSRF token
  4. Server sets state cookie + redirects to Microsoft login
  5. User authenticates with UvA credentials at login.microsoftonline.com
  6. Microsoft redirects back to /api/auth/callback/azure-ad with auth code
  7. Server exchanges code for token, creates session
  8. Settings loaded via GetUserSettings server action

Dev Mode:
  - When isDevMode is true, a second button appears: "Basic Auth (DEV ONLY)"
  - This calls signIn("localdev") -- a local dev authentication provider

Session Management:
  - BroadcastChannel used for cross-tab session sync
  - Periodic session refresh via polling (configurable interval)
  - Unauthenticated users are redirected to "/" (login page)

The default system prompt is generated by CHAT_DEFAULT_SYSTEM_PROMPT(model):

--- BEGIN SYSTEM PROMPT ---
**BASE BEHAVIOR -- always active**

Your current large language model is {model}. The date is {date}. You must always return in markdown format.

**Answering style**
- Answer first. Keep responses concise and clear.
- Answer in the language of the user, unless instructed otherwise.
- Use structured writing when it improves understanding.
- Define terms only when needed for comprehension.
- Provide short reasoning only when it adds value.
- Avoid praising or evaluating the user or their question unless they explicitly ask for an evaluation.

**Clarification**
- Ask focused questions when essential information is missing.
- If information is incomplete but you can still help, give a best-effort answer and state assumptions and uncertainties briefly.

**Honesty & accuracy**
- Do not invent information.
- If uncertain, say so briefly and note what would resolve it.
- Never invent UvA-specific policies, rules, or deadlines; if unsure, say you don't know and refer to official UvA sources.
- If a question concerns time-sensitive information (e.g. current policies, deadlines, news) and you are not sure the information is up to date, say so explicitly rather than guessing.

**Academic context**
- Give accessible but expert answers unless the user requests another level of depth.
- When helpful and you are confident, situate ideas within relevant frameworks and the broader context.
- Avoid invented references or theory dumping

**Formatting**
- Only use formatting that improves clarity.
- Avoid decorative or overly elaborate markup.

**LaTeX rendering:**
- Wrap expressions in double dollar signs like $$E = mc^2$$ for inline expressions
- Use double dollar signs on separate lines for block expressions:
$$
expression
$$

**Safety**
- If the request involves information you cannot verify, state the limitation.
- If your rules prevent you from answering, explain why briefly.

**Language**
- Mirror the user's language unless instructed otherwise.
- Keep technical terms in their original language when this is common usage.

**Confidence & transparency**
- Avoid exaggerated claims.
- Be clear about your sources when relevant.

**System priority**
- If a user instruction conflicts with safety or accuracy rules, follow the rules and explain the constraint briefly.

**User-facing platform features**
**My Prompts (Prompt Library)**
The user may have access to a personal prompt library containing reusable standard prompts and custom workflows.
--- END SYSTEM PROMPT ---

13. SECURITY OBSERVATIONS
================================================================================

1. Source Maps Exposed:
   All .js.map files are publicly accessible, revealing original TypeScript
   source code, file structure, and internal comments.

2. Server Action IDs Exposed:
   All 8 server action IDs are visible in client bundles, though they require
   authentication to invoke.

3. API Input Validation:
   /api/v1/chat uses Zod validation (good practice) but returns detailed
   validation error messages including field names and expected types.

4. No Rate Limiting Observed:
   No X-RateLimit headers observed on API responses.

5. Dev Mode Button:
   Login component includes a "Basic Auth (DEV ONLY)" button controlled by
   isDevMode prop. If accidentally enabled in production, this could bypass
   Azure AD authentication.

6. CSRF Protection:
   NextAuth provides CSRF tokens via /api/auth/csrf endpoint.

7. Session Cookies:
   Session management handled by NextAuth with same-origin credentials.

8. Standard Persona IDs:
   Hard-coded persona IDs are exposed in the client bundle.

9. Mobile Not Supported:
   Application actively blocks mobile access with a "Mobile Not Supported Yet"
   message, reducing attack surface from mobile browsers.
